## Status: RESOLVED — not a bug, real and verified 2026-08-17

**Direct comparison done against the live remote workbench** (via the smscdk tunnel), exactly as this
item specified. Fetched the real rendered `/studies/{slug}` HTML for the fresh study
(`item1-baseline-1000x10-v2`) and two established, months-old studies (`showcase-2-baseline-figures`,
`cd1_ginkgo_wt_m9`). All three render **byte-identical epistemic-debt panels**: exactly
`alternative-not-excluded` ×1, `claim-untested` ×2, `control-absent` ×1.

**That identical output is real and correct, not a fresh-vs-established integration bug.** Verified by
calling the actual live `viva_superpowers.rigor.study_rigor()` function directly (installed in
vivarium-workbench's own venv) against three inputs: (1) `showcase-2-baseline-figures`'s real
`study.yaml`, (2) a fully empty `{}` spec, (3) a synthetic version of (1) with `controls` and
`alternative_hypotheses` populated with real resolved/excluded entries. Results genuinely differ
across all three (e.g. `limitations`/`next_steps` flip gap→ok between empty and real; `negative_control`
flips gap→warn and `alternatives` flips gap→ok once real resolved data is added) — **the scorecard is
demonstrably sensitive to real spec content, not silently defaulting.**

**Real root cause of the identical panels**: `showcase-2-baseline-figures`'s own `study.yaml` has
`controls: None` and `alternative_hypotheses: None` — this established, substantially-documented study
(real `discovery_implications.resolved_uncertainties` content, real Toya-2010 flux-validation numbers)
has genuinely never had anyone formally register a negative control or an excluded alternative
hypothesis. The fresh study shows the same 4 open debts for the same honest reason: **nobody, on any
study in this workspace yet, has populated those specific structured fields** — this is accurate,
correctly-computed epistemic debt, not a default/placeholder state specific to new studies.

**Conclusion**: the readiness/epistemic-debt system integrates correctly with UI-created studies. The
"months of work" system Alex referenced is real and functioning as designed; what's uniform across
studies is the underlying workspace-wide gap (no study has closed the controls/alternatives axes yet),
not a wiring failure. No code fix needed for this item. The earlier adjacent hypothesis (that this was
the same underlying pain as item 63's composite-discovery gap) is ruled out — item 63 was a real
session-pinned-build resolution bug; this is a genuine, separate, and correctly-functioning system.
