`v2ecoli.composites.ecoli_baseline.ecoli_baseline`'s real batch/lineage-mode

## Root cause CONFIRMED (read-only investigation, verified against the exact
pinned versions build 64 actually runs — bigraph-schema `3322e39a`/v1.6.0,
process-bigraph `d8c8c641`/v1.8.3, not a possibly-stale local checkout)

`bigraph_schema/methods/realize.py`'s `realize_link` has two branches for
building a Link's `'instance'`: fresh construction (defensively binds
`.core` if missing, line ~677) and pre-built-instance-supplied (`'instance'
in encode`, no equivalent check, line ~616-633) — **a real, generic asymmetry
in bigraph_schema itself.** `Edge.__init__` normally makes `core=None`
impossible (raises if missing) — so whatever hits this crash was NOT built
through that guarded constructor.

**v2ecoli lands in exactly this gap**: `v2ecoli/composites/_helpers.py`'s
`_make_instance()` (used 9+ times in `ecoli_baseline.py`) constructs
instances directly and embeds them pre-built. Worse, `EcoliStep`/
`EcoliProcess`-based classes bypass `Edge.__init__` entirely and fall back to
a **bare, unsynchronized module-level global** (`_CURRENT_CORE`,
`v2ecoli/library/ecoli_step.py:16,219-222`) when no `core` kwarg is passed —
a real, fragile pattern independent of the bigraph_schema gap.

**Why this is new territory, not old code suddenly failing**: batch/lineage
mode runs with TWO separate `Core` objects (the outer composite's, plus
`LineageProcess._build_generation()`'s own independently-built
`core = build_core()`) — single-cell mode, verified bit-identical by the
original rename PR, only ever has one. Matches items 55/56's own pattern:
this exact composite/mode combination is getting real production traffic
for the first time.

**Ruled out with real rigor, not assumed**: traced `state["batch"]`'s actual
content (`BatchBaselineRunner.update()` → `dispatch_batch()` →
`_per_seed_results()`) — plain summary dicts, no embedded instances. NOT the
crash site. Still unconfirmed: the exact field (very likely
`v2ecoli/workflow/run.py`'s `run_workflow()` or `meta_composite.py`, per
`ecoli_baseline.py`'s own docstring — not yet read).

**Fix options, per this session's own item-51 A+B-synthesis precedent**:
(a) bigraph-schema: add the same core-binding guard to `realize_link`'s
pre-built-instance branch — general, defensive, touches an EXTERNAL repo
outside this ecosystem's own 7. (b) v2ecoli: remove `_make_instance`/
`EcoliStep`'s reliance on the fragile `_CURRENT_CORE` global, make `core`
required (already threaded at every checked call site) so a truly missing
core fails loudly instead of silently. Doing both matches this session's
standing preference for root-cause-plus-defensive over either alone.
