## Goal

`v2ecoli.types.quantity.Quantity._serialize_state` must handle a real `float`
state value without crashing, so a real chain-dispatch generation job can
write `final_state.json` successfully instead of failing at the very last
step after simulation compute has already completed.

## Why this is needed

Discovered live, 2026-08-16, firing item 52's SECOND pilot validation dispatch
(sim 153, `atlantis simulation run item52-pilot-2x2-cli-v2 63 --seeds 2
--generations 2 --run-parca`) immediately after item 55's fix went live. This
is a **different, new bug** from item 55 — not a recurrence.

**Real good news first, verified via actual CloudWatch logs, not assumed**:
item 55's fix genuinely works. Both seed0-gen0 and seed1-gen0 got past ParCa,
formed a real Ray cluster, and ran genuine simulation compute — seed1's log
shows a real mid-simulation solver event (`Warning: switching to LSODA method
in TCS`), proving actual biological step-loop execution happened, not an
immediate pre-run failure like item 55's.

**Real failure**: both jobs crashed identically, ~65s real container runtime,
`exit code 1`, right at the very last line of `run_pbg.py`'s `run()`:

```
File "/tmp/run_pbg.py", line 223, in run
    out.write_text(json.dumps(composite.serialize_state(), default=str))
...
File "/app/v2ecoli/v2ecoli/types/__init__.py", line 22, in _serialize_quantity
    return schema._serialize_state(state)
File "/app/v2ecoli/v2ecoli/types/quantity.py", line 65, in _serialize_state
    'magnitude': serialize(self.magnitude, state.magnitude),
AttributeError: 'float' object has no attribute 'magnitude'
```

Confirmed **deterministic, not a data-dependent fluke** — both seed0-gen0 and
seed1-gen0 hit the exact identical traceback at the exact identical line.

**Root cause, read directly from the real deployed source** (`git show
c44b69a:v2ecoli/types/quantity.py`, the exact commit build 63 was built from —
not the separately-diverged local v2ecoli checkout):

```python
def _serialize_state(self, state):
    if isinstance(state, dict):
        return state
    if isinstance(state, int):
        return {
            'units': self.units,
            'magnitude': serialize(self.magnitude, state),
        }
    return {
        'units': self.units,
        'magnitude': serialize(self.magnitude, state.magnitude),
    }
```

This method has 3 branches: already-serialized dict (pass through), raw `int`
scalar (serialize directly), or else — assumed to be a pint `Quantity`-like
object with a real `.magnitude` attribute. **The `int` branch was never
extended to cover `float`**, so a real `float` state value falls into the
`else` branch and `.magnitude` fails. `isinstance(state, int)` does not match
`float` in Python — this is a real, narrow gap in the existing branch, not a
missing concept.

**Leading, unconfirmed hypothesis for why this has never been hit before**:
this is very likely the FIRST real end-to-end lineage/chain-dispatch execution
of `v2ecoli.composites.ecoli_baseline.ecoli_baseline` in its batch/lineage
mode (`n_seeds`/`n_generations` > 1) — item 55's fix is what made this
composite reachable via chain-dispatch at all. Every prior real production
dispatch used the old, now-deleted `batch_baseline.batch_baseline` composite.
The code itself (`quantity.py`) has existed since 2026-04-14/18 (`fe84b34e`,
`28201f65`) — not new — so this is a real, latent gap that this exact
composite/mode combination is the first thing to exercise. Not yet confirmed
by diffing state-shape between the two composites; stated as the most
plausible explanation, not asserted as fact.

## Proposed fix, not yet implemented

Per the Optimal Design Coordinates 4-question framework: question 1 — an
existing mechanism (the raw-scalar branch) already exists and just needs its
condition widened, no new concept needed:

```python
if isinstance(state, (int, float)):
```

Minimal, precise, matches the existing pattern exactly — does not broaden to
duck-typing (`not hasattr(state, "magnitude")`) which could silently mask a
different, real future bug by treating any non-Quantity object as a raw
scalar. v2ecoli-first per [[feedback-sms-ecoli-fixes-via-v2ecoli-only]]: fix
belongs in v2ecoli (`v2ecoli/types/quantity.py`), then sync into sms-ecoli,
then a fresh real pilot dispatch to validate — a clean v2ecoli-side test
alone does not mean deliverable-ready, matching item 52's own precedent.

Needs: the fix itself, a real regression test asserting `_serialize_state`
handles a plain `float` state without raising (would fail pre-fix), then the
same v2ecoli PR → merge → sync into sms-ecoli → build → fresh pilot chain
already proven 3 times this session (items 51/52/55). Held for explicit
go-ahead before implementing, given this is real v2ecoli scientific-model
code (not viva-api glue) and this is the third unplanned bug surfaced by this
same chain.
