## Goal

Fix a `bigraph_schema` `Link` `_outputs` serialization crash — an `Array`-typed schema's `_data`
field is a raw Python `str` instead of a `numpy.dtype` instance, crashing numpy's
`dtype_to_descr`/`drop_metadata` at the very last step of a real simulation run.

## Why this is needed

Discovered 2026-08-16 firing sim 155, the 4th item-52 wall-time pilot (the first with items 55/56/57
all fixed simultaneously). Real, deterministic crash on both `seed0-gen0` and `seed1-gen0`
(identical `AttributeError: 'str' object has no attribute 'fields'`), each after ~66s of genuine
compute (real Ray cluster formed, real solver activity — seed1's log shows a genuine mid-simulation
`Warning: switching to LSODA method in TCS`). Blocks item 52's wall-time validation — this is the
4th distinct pilot failure in a row, each a different bug (55, 56, 57, now this).

## Status: FIXED — v2ecoli PR #512 open, held for merge

Real root cause: `register_labeled_array()` (`v2ecoli/types/labeled_array.py`) always stringified
its `data=` argument before registering it, even when callers already passed a real `np.dtype` —
registering via an `_inherit` key (not `_type`) bypasses bigraph_schema's normal type-normalization
path entirely, so the string sailed through uncaught. Two real call sites (`CountsDeriver`,
`RnapData`), both wired into `ecoli_baseline` and `ecoli_millard` (same copy-paste-across-composites
shape as item 57). Fix: 2-line diff, always register a real `np.dtype`. 2 new regression tests
exercise the real composite via the ParCa-fixture cache, fail-then-pass verified via git stash.
Full gate suite clean against a baseline worktree; PR's own CI: all 7 checks pass (fresh-verified,
`mergeStateStatus: CLEAN`). Confirmed v2ecoli-only — no bigraph_schema change needed or made.

**Independently corroborated by 2 side-investigation agents (different methods, same conclusion)**:
the bigraph_schema code that crashes in items 57/58 has been unchanged for 4-9+ months (dormant,
never regressed) and — for item 58 specifically — never validated its `dtype` input at any point in
its history. The bug is old; the exposure (v2ecoli's `ecoli_baseline` batch/lineage-mode composite
code hitting these paths for the first time) is new.

**PR: https://github.com/vivarium-collective/v2ecoli/pull/512** — held, not merged, awaiting go.
