## Goal

Move analysis-name/scale validation off the workbench's own client-side, in-process copy of
v2ecoli's `ANALYSIS_REGISTRY` and onto whatever system actually executes the composite — so
"what analyses are valid" has exactly one authoritative source, never a copy that can silently
drift out of sync with it.

Concretely:
- **Server-side authoritative validation**: the workbench sends a flat list of requested analysis
  names (+ params); whatever actually executes the composite (viva-api, or v2ecoli's own runtime
  at dispatch/build time) resolves names to scale and validates them, since that's the only place
  that's never stale by construction — it IS the thing running the code.
- **If client-side resolution has to stay** (e.g. for immediate UI feedback/grouping before
  submit), it must be advisory-only. The real dispatch path re-validates authoritatively,
  independent of whatever the client-side copy believed, and any name that doesn't reconcile is a
  **hard, loud failure** surfaced to the caller/UI — never a server-side-only `warnings.warn()`
  that a caller has to know to go looking for.
- Whatever shape the fix takes, it should follow the ecosystem's existing patterns (e.g. an
  existing viva-api endpoint/contract, or v2ecoli's own manifest/registry export, rather than a
  bespoke new mechanism) and land production-grade: typed, tested, and documented — not a patch.

## Why this is needed

Item 39 (`.todo/backlog/39.md`) fixed a REAL, live bug: `build_analysis_options()` (workbench)
silently dropped every `cd1_*`/`ptools_*` analysis name from remote dispatch because its own
in-process import of v2ecoli's registry was incomplete. That fix (an explicit
`import v2ecoli.workflow.analyses`) closes the SPECIFIC symptom, but not the STRUCTURAL cause:
the workbench validates analysis names against its own copy of v2ecoli's registry — a copy that
can only ever be a snapshot (whichever image/commit happens to be running), never the live truth
of whatever will actually execute the dispatch. Item 39's own original scoping already named this
exact smell directly ("make dispatch-time validation loud, not silent, regardless of which
underlying fix is chosen") — today's fix satisfies the letter of that but not the full spirit.

This is a duplicated-source-of-truth problem across a real system boundary (workbench repo /
release cycle vs. v2ecoli repo / release cycle), and it is structurally guaranteed to recur: a
stale baked-in image (already happened, item 39's Fix B), a wrong import chain (already happened,
item 39's fix today), or — the next one waiting to happen — v2ecoli adds a new analysis module and
someone forgets to wire it into whatever import path currently populates the registry. Same silent
truncation, same failure mode, third distinct root cause. Fixing the STRUCTURE (single
authoritative validator, loud failure on mismatch) closes the whole class of bug, not just this
instance of it.

Deliberately filed as its own item, not folded into item 39: this is a real redesign of where
validation authority lives, not a fix — it deserves its own scoping, design, and review, not to be
rushed in under an already-long item-39 arc.
